# Mia AI — guida per lavorare sul progetto

App di chat AI personale: **Android (Capacitor)** e **versione web/PC (GitHub Pages)**. HTML + CSS + JavaScript, senza bundler.
Lingua: **italiano** (interfaccia, messaggi di errore, commit, README, risposte al proprietario).

## Regole del proprietario (valgono sempre)
- **Solo servizi gratuiti.** Se un servizio non è gratuito non si aggiunge (per questo non ci sono Brave Search, Cerebras, ecc.). Dire sempre quali limiti non sono verificati.
- **Nessuna PR e nessuna unione senza una richiesta esplicita** («apri e unisci la PR»). Prima di unire: build verde sul commit di testa, PR `mergeable_state: clean`, unione con `merge_method: merge` e `expectedHeadSha`.
- Il push diretto su `main` è bloccato dai permessi: si lavora su un branch (nell'ambiente cloud `ccr-ee7b5fe2-286x3a`) e si passa dalla PR.
  Dopo un'unione il branch riparte da `origin/main`, ma **prima** si controlla che non ci siano commit solo sul remoto del branch (`git log origin/main..origin/<branch>`).
- **Non dire «funziona» senza averlo provato.** Distinguere sempre: provato nei test (servizi simulati) / provato dal proprietario sul telefono / non verificato.
- Segreti (token GitHub, chiavi API) mai in chat, screenshot o repository.
- Risposte concise, con le verifiche fatte e cosa resta da provare.

## Build, test, pubblicazione
- `npm run serve` → `http://localhost:8080` (prepara `www/`, che è output di build e non va committato).
- **Test:** `cd tests && npm install && npx playwright install chromium && npm test` (circa 1 minuto, servizi simulati).
  Ogni funzione nuova ha il suo test in `tests/e2e/` e le righe attese in `tests/expectations.js`.
- **CI dei test:** `.github/workflows/tests.yml` esegue `tests/` a ogni PR e a ogni push su `main` (non per le sole modifiche `.md`). Da verificare la prima esecuzione sul commit di testa prima di unire.
- **APK:** `.github/workflows/build-apk.yml` parte a ogni push (anche sui branch). Artifact `mia-ai-debug-apk`, firma fissa (le chat restano installando sopra).
  Il repository è pubblico: la chiave di firma è visibile, va bene per un'app personale, non per il Play Store.
- **Pagina web:** `.github/workflows/pages.yml` pubblica `www/` su `https://micmax1000-afk.github.io/mia-ai-app/` a ogni unione su `main`.
  Richiede, una volta, *Settings → Pages → Source: GitHub Actions*: **ora è attivo** e la pubblicazione riesce (verificato su GitHub Actions). L'apertura della pagina da un PC non è ancora stata verificata dal proprietario (dall'ambiente di sviluppo `github.io` non è raggiungibile).
  Le modifiche ai soli file `.md` (e a `tests/`) non fanno partire né il build dell'APK né la pubblicazione: per una PR di sola documentazione non c'è un build sul commit di testa, si guarda l'ultimo build verde di `main`.

## Cose da sapere (insidie già incontrate)
- `P.chat` restituisce **testo**; con `{ full: true }` restituisce `{ text, toolCalls }`. `runFileEdit` (di `main`) si aspetta una stringa.
- Gemini: conservare `thoughtSignature` nelle chiamate agli strumenti; niente `parameters` vuoti nelle dichiarazioni. Mistral: id delle chiamate di 9 caratteri alfanumerici (`toNineId`).
  Schemi degli strumenti MCP ripuliti per Gemini/OpenAI (`cleanSchema`).
- Con `CapacitorHttp` attivo (`capacitor.config.json`) su Android le richieste vanno in modo nativo (niente CORS). **Nel browser** molti servizi possono essere bloccati dal CORS (DuckDuckGo, NVIDIA, vari MCP).
- `localStorage` ha circa 5 MB: i file creati stanno in IndexedDB; `persistConvs` toglie gli allegati più vecchi se la memoria si riempie. L'importazione chat ripulisce il file (campi noti, ruoli ammessi, URL immagini solo `https`).
- Gli strumenti che modificano qualcosa devono avere `write: true` (chiedono conferma); `danger` per le azioni difficili da annullare (unione PR, eliminazione file).
  I connettori MCP non dichiarati «di sola lettura» chiedono sempre conferma. Il contenuto restituito da strumenti/pagine è **dato, non istruzioni**.
- JavaScript/Python: iframe `sandbox` + CSP (rete bloccata) + Worker terminabile. Python usa Pyodide da `cdn.jsdelivr.net` (versione fissata in `tools.js`).
- Immagini: NVIDIA FLUX (`ai.api.nvidia.com/v1/genai/black-forest-labs/flux.1-schnell`; schema verificato sulla API Reference di `build.nvidia.com`: la richiesta accetta solo `prompt`, `width`/`height` 768–1344 a passi di 64, `steps` 1–4, `cfg_scale`, `mode`, `samples` — **niente `seed`**, ogni altro campo dà 422; risposta `artifacts[0].base64` JPEG con `finishReason` SUCCESS/ERROR/CONTENT_FILTERED; i campi rifiutati vengono comunque tolti da soli), Gemini, Pollinations (`image.pollinations.ai`, indirizzo vecchio ma funzionante).
  «Automatica» prova nell'ordine NVIDIA → Gemini → Pollinations.
- **NVIDIA è un servizio «trial»** (verificato sui termini ufficiali «API Trial Terms of Service»): solo test e valutazione, non produzione (§1.2, §1.4); NVIDIA può usare testi e risposte per migliorare i suoi modelli (§3.3) e vieta di inviare dati personali, sanitari, finanziari o riservati (§4.3). Numero di crediti e limiti di richieste non sono nei termini. Non allegare dati sensibili con i modelli NVIDIA; la stessa prudenza vale per qualunque piano gratuito di terzi.
- `github_issues`/PR/Actions richiedono un token con i permessi giusti (fine-grained: Contents, Issues, Pull requests, Actions, Metadata in lettura/scrittura). Gli errori 403/404 mostrano i permessi richiesti.

## Ambiente di sviluppo cloud
- Rete filtrata da un proxy: alcuni siti non sono raggiungibili (per esempio `cdn.jsdelivr.net`, `github.io`); `build.nvidia.com`, `docs.nvidia.com`, `docs.api.nvidia.com` e `assets.ngc.nvidia.com` sono stati abilitati dal proprietario (pagine dei modelli leggibili anche in `.md`, es. `/black-forest-labs/flux_1-schnell/apireference.md`), mentre gli indirizzi delle API (`integrate.api.nvidia.com`, `ai.api.nvidia.com`) restano bloccati: quello che dipende da loro si prova con simulazioni e va verificato sul telefono. `WebSearch` funziona.
- Niente CLI `gh`: per GitHub si usano gli strumenti MCP. Chromium e Playwright sono preinstallati (`/opt/pw-browsers`, versione 1.63.0 — la stessa fissata in `tests/package.json`).

- **PDF:** `fileToAttachment` salva `att.text`/`att.pages` (pdf.js). Gemini e OpenRouter ricevono il file; gli altri provider ricevono il testo estratto (`textWithFiles(m, nativePdf)`); PDF senza testo + provider senza lettura nativa → errore chiaro. `pdfText` usa `task.destroy()` (non `doc.destroy()`).
- **OCR NVIDIA** (`ocrScan` in `app.js`, `MiaTools.ocrImages`, `MiaDocs.pdfPageImages`): per i PDF senza testo, con chiave NVIDIA e **solo dopo conferma** (le pagine vanno a un servizio di prova). Richiesta dalla pagina ufficiale: `POST ai.api.nvidia.com/v1/cv/nvidia/nemoretriever-ocr` con `{input:[{type:'image_url',url:'data:image/jpeg;base64,…'}]}`, immagine sotto i 180000 caratteri; **la forma della risposta del servizio ospitato non è documentata**: `ocrTextOf` legge `data[].content`, `text_detections[].text_prediction.text`, `text`. Da verificare sul telefono. Massimo 10 pagine; dopo 2 errori di fila si smette.
- **FLUX.1 dev:** `settings.nvidiaImageModel` (`flux.1-schnell` | `flux.1-dev`); stesso schema, `steps` 30 per dev (5–100). La pagina ufficiale elenca 768–1344 ma nel testo dice «solo 1024»: se il servizio rifiuta il formato, `nvidiaImage` toglie `width` e `height` insieme (1024×1024).
- Il filtro dei modelli NVIDIA (`providers.js`) nasconde anche `riva-translate` (traduttore, non chat); `content-safety` era già nascosto.
- **Connessione caduta** (Android: «Software caused connection abort»): `P.isConnectionError`; in `runAssistant` `chatWithRetry` riprova fino a 2 volte con lo stesso modello (1,5 s e 3 s), poi, con il ripiego automatico attivo, passa al modello successivo. L'interruzione dell'utente (`AbortError`) non si riprova.
- **File lunghi su GitHub** (incidente reale: `data.js` di 228 KB / 4013 carte sostituito da uno di 10 KB): `Tools.run` taglia ogni risultato a `MAX_RESULT` (12000) e il vecchio avviso di troncamento nascondeva quanto mancava. Ora `github_read_file` ha `maxResult: 45000` (cap per strumento), legge a blocchi (`start`, `length`) o cerca (`find`) e dice «FILE INCOMPLETO … NON riscrivere»; `github_write_file` su un file esistente > 2000 caratteri che si riduce sotto il 50 % chiede una **seconda conferma** (`ctx.confirm`, danger) e senza conferma non scrive. Per cambiare file lunghi si usa `github_edit_file`.
- **Solo il repository selezionato:** `settings.githubScope` (di serie `true`) + `settings.githubRepo` → `ctx.repoLock`/`ctx.repoScope`; `Tools.applyScope` (chiamata in `runOneTool` e in `Tools.run`) completa `owner`/`repo`, rifiuta altri repository, forza `github_search_code` sul repository, blocca `github_create_repo`, e senza repository selezionato blocca tutti gli strumenti `github_*`. I connettori MCP (anche quelli GitHub) **non** sono coperti.
- **Branch di lavoro** (`settings.githubUseBranch`, di serie `true`; `githubWorkBranch`, di serie `mia-lavoro`, mai `main`/`master`): `Tools.applyBranch` forza `branch` per `github_write_file`/`edit_file`/`delete_file` e `ref` per `github_read_file` (se il branch non esiste ancora si legge il principale); `ensureWorkBranch` crea il branch dal principale e lo riallinea (PATCH senza force) solo se non ha commit propri (`compare` ahead_by 0).
- **Sintassi prima di salvare:** `syntaxError(path, text)` per `.js`/`.cjs` (`new Function`, solo analisi, poi `AsyncFunction` per `await`; moduli con `import`/`export` non controllabili) e `.json`; `checkSyntaxOrThrow` rifiuta se il file era valido e diventerebbe rotto, avvisa se lo era già. `github_edit_file` restituisce righe prima → dopo e ±3 righe numerate intorno a ogni sostituzione; la conferma mostra «Righe: −a / +b» e diventa `danger` con 20+ righe nette tolte (`editLines`).
- **`github_delete_lines`** (cancella le righe `from_line`–`to_line`, numerate come in `find`): richiede `expect_first`/`expect_last` (confrontati senza distinzione di spazi/maiuscole con la prima e l'ultima riga), `dry_run` mostra i bordi senza scrivere né chiedere conferma, limite 5000 righe, controllo sintassi, conferma `danger` da 20 righe; passa per `applyScope`/`applyBranch`. Dopo ogni cancellazione i numeri di riga cambiano: l'esito lo ricorda. Passi massimi dell'agente: da 3 a 100 (`maxSteps`, di serie 15).
- **Istruzioni dell'agente** (`agentPrompt` in `app.js`): testo strutturato (come lavori / file e codice / onestà / altri strumenti): capire → piano se grande → un passo e controllo dell'esito → fermarsi se non è come atteso; mai riscrivere file esistenti; copiare i dati esattamente; `must_count`; `github_compare` e `github_actions branch_status` a fine lavoro; mai dire «fatto» senza verifica; risposta finale con cosa cambiato / come controllato / cosa non verificato. In coda, le **regole del progetto** (`Tools.projectRules`: `MIA.md`, poi `AGENTS.md`, `CLAUDE.md` del branch principale, cache 5 min, max 4000 caratteri).
- **Leggere prima di scrivere** (`settings.githubReadFirst`, di serie `true`; `readState(c)` in `app.js` ricava dalla cronologia i file letti: `read` = letti anche in parte/con find o scritti/modificati dal modello, `full` = letti per intero in una volta o scritti per intero): `github_edit_file`, `github_delete_lines` (non in `dry_run`) richiedono `read`; `github_write_file` su un file esistente richiede `full`. Controllo in `needRead` (`tools.js`) con `ctx.readGuard`/`ctx.readState`.
- **Regole sul contenuto:** parametro `must_count` (`[{text, equals|change}]`) su edit/write/delete_lines: dopo l'operazione il numero di occorrenze di `text` deve valere `equals`, o variare di `change`; altrimenti non si salva (`checkMustCount`).
- **Contesto nei lavori lunghi** (`buildHistory`): `MAX_HISTORY` 60 messaggi; restano sempre nel contesto le ultime 3 richieste dell'utente e l'ultima richiesta «vera» (≥ 40 caratteri), fino a `MAX_HISTORY_HARD` 220 messaggi; oltre, la richiesta resta in testa e poi i passaggi recenti. Incidente reale: dopo molti passi con strumenti «continua» arrivava al modello da solo (la richiesta era uscita dalla finestra) e il modello non sapeva cosa fare. Risultati di strumenti: ultimi 6 interi, poi 1500 caratteri, oltre 24 passi 300.
- **Modelli di ripiego** (`settings.fallbacks`, `renderFallbacks`/`bindFallbacks`): elenco ordinato, separato da `favorites` (i preferiti servono al cambio rapido e si riempiono da soli); alla prima apertura si copia da `favorites`. `runAssistant` prova `fallbacks` (non il modello corrente, solo se `isConfigured`, al massimo `MAX_FALLBACKS` = 8).
- **Schermo acceso** (`keepAwake`/`applyAwake`, agganciata a `setBusy`): `nativePlugin('KeepAwake')` (`@capacitor-community/keep-awake` 7.1.0 in `package.json`, registrato da `cap sync`) altrimenti `navigator.wakeLock`; si riprende al `visibilitychange` visibile. **Non provato su Android vero** (né il plugin né il Wake Lock nella WebView).
- **Ripresa automatica** (`tryResume`, `scheduleResume`, `resumeInterrupted`): gli errori di connessione sono `resumable`; dopo l'errore (4 s), a `online` e al ritorno in primo piano si rilancia `runAssistant` (max 3 riprese per chat, `resumeCount`). All'avvio `resumeInterrupted` riprende un lavoro con ultimo messaggio `tool`/`user` e `updated` < 15 min (`RESUME_WINDOW`), togliendo una richiesta di strumenti senza risultati; `c.stopped` (fermato dall'utente) la impedisce.
- **Secondo parere / riepilogo** (`secondOpinionText`, `workSummaryText`, `askOpinion`, `shareDoc` in `app.js`): pulsanti `data-act="opinion"` / `"summary"` sotto le risposte; il compito parte dall'ultima richiesta utente «vera» (`taskStart`, ≥ 40 caratteri); condivide con `shareText` (≤ 8000 caratteri) o come `.md` con `Files.shareBlob`; `c.opinionAt` (2 ore) fa etichettare come «Parere di un'altra app» il testo che arriva dal Share Target (`CapacitorShareTarget`), che accetta anche file `text/*` e PDF oltre alle immagini.
- **«Stop» e richieste non interrompibili** (incidente reale su Android): con `CapacitorHttp` il `fetch` nativo **ignora l'AbortSignal** e risponde solo a richiesta finita, quindi «Stop» sembrava non funzionare. `P.raceAbort(promise, signal)` (anche in `tools.js`) fa fallire subito la promessa con `AbortError`: usato in `P.chat`, `Tools.run`, preparazione dell'agente (`refreshMcp`, `agentPrompt`) e nella pausa tra i tentativi di `chatWithRetry`. **Attenzione:** una scrittura nativa già partita (commit su GitHub) può comunque completarsi anche dopo «Stop»; Mia smette solo di aspettarla.
- **Hugging Face:** `friendlyError` spiega 402 (crediti), 403 (permesso «Make calls to Inference Providers»), 401 (token), modello non disponibile; avviso alla chiusura delle Impostazioni se il token non inizia con `hf_`. **Non provato con il servizio vero** (`router.huggingface.co` non è raggiungibile dall'ambiente di sviluppo).
- **Velocità e streaming su Android** (`streamFetch` in `providers.js`; `speedText`, `recordSpeed`, `renderSpeedStats` in `app.js`): `window.CapacitorWebFetch` (fetch originale del browser, che Capacitor tiene da parte quando `CapacitorHttp` è attivo) per gli host `generativelanguage.googleapis.com`, `api.groq.com`, `api.mistral.ai`, `openrouter.ai`: il testo arriva in streaming; se fallisce prima della risposta (CORS/rete) si ripiega sul `fetch` nativo e l'host entra in `nativeOnly` per la sessione. NVIDIA e gli altri restano nativi. Ogni messaggio dell'assistente ha `msg.speed = {ms, first, chunks, words}` (si misura l'ultimo tentativo); `settings.speedStats` tiene la media mobile per modello (max ~40 risposte), `showSpeed` mostra l'etichetta. **Non provato su Android vero**: che `window.CapacitorWebFetch` esista come previsto, e che quei servizi accettino richieste dal WebView (CORS), è da verificare.
- **Impostazioni a tendine** (`details.set-sec` / `details.set-sub` in `index.html`; `restoreSections`, `updateSummaries` in `app.js`; stato in `localStorage` `miaai_set_open`): i campi restano nel DOM anche con la sezione chiusa, quindi `closeSettings` li salva comunque. **Nei test** dopo aver aperto le Impostazioni si aprono tutte le sezioni con `document.querySelectorAll('details.set-sec,details.set-sub').forEach(d=>d.open=true)`.
- **Pausa dei modelli** (`coolUntil`, `pauseModel`, `orderByPause`): su errore «occupato/limite» (`P.isBusyError`) il modello è saltato 2 minuti (60 se «giornaliero»); a ogni passo `runAssistant` riordina i candidati (prima i disponibili, poi quelli in pausa dal primo a ripartire). `MAX_FALLBACKS` = 8. Con più modelli falliti il messaggio dice «Nessun modello ha risposto. Ho provato: …» (`triedLog`).
- **Versione dell'app:** `package.json` `version` (0.3.0); il workflow imposta in `android/app/build.gradle` `versionCode` = `GITHUB_RUN_NUMBER` e `versionName` = `versione.run` (il passo fallisce se il `sed` non cambia il file); `scripts/stage-www.js` scrive `www/version.json`; l'app mostra la versione con `App.getInfo()` (Android) o `version.json`. Per un APK installabile sopra serve solo che il numero cresca e la firma resti la stessa. `patch-android-manifest.py` aggiunge anche i filtri `text/*` e `application/pdf` per ricevere file da altre app (**non provato su Android**).
- **Repository per chat** (`c.repo`, `chatRepo()`, `setChatRepo`, `pendingRepo`, `rememberRepo`, riquadro `#repoBtn` e `#repoSheet`): una chat nuova parte con `repo: ''` (salvo `settings.githubNewChatRepo`); le chat già salvate senza `repo` ricevono `settings.githubRepo` al caricamento; `settings.githubRepo` resta il «predefinito» (Impostazioni → GitHub, usato anche da «Fai leggere il repository» e «Modifica e push»). `toolContext().repoScope`, `agentPrompt`, `projectRules` e il riepilogo usano `chatRepo()`. `cleanConversation` conserva `repo` e `usage`. **Nei test** che usano l'agente con un repository si imposta `githubNewChatRepo:true` insieme a `githubRepo`.
- **Contatore dei token** (`usage` di ogni risposta dell'assistente: `{key:'provider|modello', in, out, think, est}`; `recordUsage` → `settings.usageStats['AAAA-MM'][key]`, ultimi 3 mesi; `settings.prices[key] = {in, out}` in $/milione, nessun prezzo precompilato): i token veri vengono da `usageMetadata` (Gemini) o `usage` dell'ultimo pezzo (OpenAI-compatibili; **non** si invia `stream_options` per non rompere i provider); altrimenti `finishUsage` stima (`estimateTokens` = caratteri/3,6, immagini 800, base64 ignorato) con `est: true`. La barra `#usageBtn` somma i messaggi della chat; il riquadro `#usageSheet` mostra chat e mese e i campi prezzo.
- **Mappa e struttura con acorn** (`js/vendor/acorn.js`, caricato da `warmAcorn()` solo quando serve; se non si carica resta il vecchio controllo con `new Function`): `syntaxError` ora controlla anche i moduli (`import`/`export`) e dà «riga N, colonna M». `github_outline` (sola lettura, nessuna conferma) elenca funzioni, classi, variabili, elementi di array (con `id`/`name`…) e chiavi di oggetto con le righe, anche dentro `(function(){…})()`; `.json` e `.md` (titoli) inclusi; `symbol` e `max_items` per restringere. `github_edit_structure` (`write`, `dry_run` senza conferma): operazioni `remove_element` (per `match` su proprietà, uno solo salvo `all`/`expect_matches`), `add_element` (rifiuta doppioni per `id`/`name`…, `position` start/end/after), `remove_property`, `remove_declaration`; il file viene rianalizzato dopo ogni operazione, vale `must_count`, controllo sintassi, `applyScope`/`applyBranch`, e per scrivere serve aver letto o mappato il file (`readState`: `github_outline` conta come lettura parziale). Le istruzioni dell'agente dicono di usare la mappa invece di rileggere i file. **Non provato con GitHub vero né con file reali grandi** (solo test 40 con GitHub simulato).
- **Conferma con differenze e prova del codice** (`confirmExtras`, `renderDiff` in `app.js`; `MiaTools.preview`, `lineDiff`, `diffText`, `codeCheck` in `tools.js`): per gli strumenti di scrittura su file, mentre il riquadro di conferma è aperto, `preview` esegue lo strumento con `ctx.preview` (in `gh()` la PUT/DELETE su `/contents/` viene catturata e **non** parte; se il branch di lavoro non esiste ancora si guarda il principale) e si mostrano le righe tolte (rosso) e aggiunte (verde) con i numeri. `codeCheck` esegue il file prima e dopo nella sandbox (solo script `.js`/`.cjs`, con `window = globalThis`; se non si può eseguire da solo si dice) e confronta i conteggi di primo livello (`topCounts`). **Niente revisore interno** (tolto su richiesta del proprietario: il parere si chiede ad app esterne).
- **Annulla modifiche** (`undoButton`, `undoTurn`; `MiaTools.undoPlan`, `undoApply`): `gh()` comunica ogni PUT/DELETE su `/contents/` a `ctx.onCommit` (`{base, path, branch, oldSha, newSha, commit, deleted}`), salvati in `tm.commits` (anche in `cleanConversation`). Sulla risposta finale del turno compare «Annulla modifiche»: ogni file torna al blob di prima (`git/blobs/{oldSha}`) o viene eliminato se era nuovo, con un nuovo commit; conferma rossa se il file è cambiato dopo (`sha` diverso da `newSha`) o se è sul branch principale. Dopo: `tm.undone`, etichetta «↶ modifiche annullate» e nota nel `context` della risposta per il modello.
- **Cambio di modello dopo 2 errori di fila** (in `runAssistant`, `failStreak`): se lo stesso strumento fallisce 2 volte di fila (rifiuti dell'utente esclusi), il modello che ha risposto va in fondo a `attempts` per il resto del lavoro e continua il successivo (con `autoFallback` attivo); le risposte successive hanno «↪».
- **Mappa del progetto** (`MiaTools.projectMap`, in `agentPrompt` dopo le regole del progetto): elenco dei file del branch principale (`git/trees?recursive=1`, senza `node_modules`/`dist`/`www`…) e voci di primo livello dei 3 file `.js`/`.json` più grandi; cache 10 minuti; errori ignorati. Si prepara **in background** (`preloadMap` in `renderMessages`, `projectMap(..., {noWait:true})`): l'agente non la aspetta (con rete lenta bloccava l'avvio, visto nel test 36), quindi alla prima richiesta può non esserci ancora.
- **Memoria:** `settings.memory` (una riga per fatto) è aggiunta al prompt di sistema in `chatConfig` come dato; strumento `memory` con conferma per add/remove. `memoryUpdated` serve alla sincronizzazione.
- **Sincronizzazione:** token e `syncRepo` dalle impostazioni; si sincronizza solo a risposta finita (`busy` falso). Dopo una sincronizzazione il pannello Impostazioni può essere aperto: aggiornare i campi del pannello (`#memory`), altrimenti `closeSettings` riscrive i valori vecchi. Eliminando chat si scrive `settings.deletedChats` (`markDeleted`).
